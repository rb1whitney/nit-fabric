# SRE Runbook: Multi-Cloud CIDR Overlap Conflict Resolution

## 1. Alert Metadata
*   **Alert Name**: `SRE_CIDR_Overlap_Conflict`
*   **Severity**: **P1 - Critical (Blocked Deployment)**
*   **SLA / Time-to-Mitigate**: 15 minutes (CI/CD pipeline blocks)
*   **Target Components**: IP Address Management (IPAM) Vault, Z3 SMT Theorem Prover, Terraform modules.
*   **PagerDuty Escalation Policy**: `DevOps-Lead-Oncall`

---

## 2. Triggering Alert Criteria
This runbook is triggered when the CI/CD pull request gate throws an `OverlapConflictError` or `Z3IPAMConflictException` during preflight checking.
```text
Z3IPAMConflictException: Bit-vector solver proved overlap between subnets!
  Proposed Subnet A: 10.100.12.0/22 (AWS)
  Existing Subnet B: 10.100.8.0/21 (GCP)
  Proven Overlapping Range In Model: [10.100.12.0 - 10.100.15.255]
```

---

## 3. Triage & Quick Diagnostics

### Step 3.1: Reproduce Solver Proof Locally
To view the exact SMT model proving the address intersection, execute the `nit-fabric` solver validation suite locally:
```bash
# Run local dry-run scan to extract conflict details
PYTHONPATH=src python3 src/nit_fabric/main.py scan --mode mock
```
If an overlap exists, the command exits with code `1` and outputs a complete mathematical proof generated by Z3:
```text
=== Z3 SOLVER MODEL PROOF ===
Subnet 'Proposed AWS Web' (10.100.12.0/22) overlaps with 'GCP GKE Node Subnet' (10.100.8.0/21).
Conflict Intersection Boundary: 10.100.12.0 to 10.100.15.255.
============================
```

### Step 3.2: Query IPAM Registry State
Query the current registered CIDR allocations across the fabric:
```bash
# View JSON IPAM registration registry
cat .agent/skills/registry.json
```
Verify the allocated and unallocated blocks to identify where the overlap conflict occurred.

---

## 4. Remediation Steps

### Step 4.1: Compute Next Free Disjoint Block
Use the `nit-fabric` solver module to find the next available, completely disjoint CIDR block of the required prefix size:

1.  **Check IPAM available bounds** inside `.agent/skills/registry.json`.
2.  **Verify the conflict model**: The conflict exists because the proposed subnet `10.100.12.0/22` intersects with the larger block `10.100.8.0/21` (which spans `10.100.8.0` to `10.100.15.255`).
3.  **Identify target range**: The next available disjoint block of size `/22` must start at or after `10.100.16.0`.

### Step 4.2: Generate and Validate Remediation Patch
1.  **Generate HCL Patch**:
    Locate the variables or subnet resources inside `terraform/main.tf` or variables files, and update the CIDR allocation:
    ```diff
    -  cidr_block = "10.100.12.0/22"
    +  cidr_block = "10.100.16.0/22"
    ```
2.  **Validate Patch Mathematically**:
    Run `remediate` with Z3-solving validation enabled to confirm that the new block is completely disjoint from all existing multi-cloud subnets:
    ```bash
    PYTHONPATH=src python3 src/nit_fabric/main.py remediate --provider terraform
    ```
    If successful, the console will output:
    ```text
    Verification Gate Passed: No overlapping CIDRs detected.
    Z3 SMT Solver: Satisfiable, subnets disjoint.
    Patch HCL syntax verified successfully.
    ```

### Step 4.3: Deploy Safe Changes
Commit the validated HCL patch directly to the feature branch to unblock the PR gates:
```bash
git add terraform/
git commit -m "fix(ipam): resolve Z3 CIDR overlap conflict by allocating 10.100.16.0/22"
git push origin feat/nit-fabric-agents-standardization
```
